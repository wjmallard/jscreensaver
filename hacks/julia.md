# julia — port notes

A continuously varying **Julia set**: the complex parameter `c` walks a small orbit, and the set `z -> z^2 + c` is recomputed every frame so it smoothly morphs. A small white ring marks the current `c` (the xml's "control point from which the rest of the image was generated").

Original: <https://www.jwz.org/xscreensaver/> · source: `xscreensaver-6.15/hacks/julia.c` by Sean McCullough, 1995/1997 (~450 lines) + `config/julia.xml`.

## Algorithm
- **Per-pixel escape-time.** For every pixel, map it to a complex point `z0` (the short axis spans the complex range `[-2, 2]` at zoom 1) and iterate `z -> z^2 + c`, counting iterations until `|z| > 2` (bailout) or a max iteration count is reached. In-set pixels (never escape) are painted **black**; escaped pixels are coloured by a **smooth** (fractional) escape count `n + 1 - log2(log2(|z|))`.
- **Colour.** A full hue wheel (`ncolors` entries) indexed by `floor(smoothN / ITERS_PER_CYCLE * ncolors)`, so escape contours form tight rainbow bands (~12 iterations per full rainbow trip). `Color cycling` slowly rotates that palette over time.
- **Morphing `c`.** Each frame `c` advances along the C's `incr()` sinusoidal (Lissajous-like) orbit, scaled and clamped to stay near the detail-rich Mandelbrot boundary (see Deviations), then the whole field is recomputed. The control ring is drawn at the screen position of `z == c`, exactly as the C draws its `c`-circle.

Rendering uses the **blit + upscale path** (`hack-rendering-perf` rule): the field is computed into a `Uint32Array` view over one `ImageData` on a small offscreen canvas, then `drawImage`-upscaled to the device-pixel canvas. Skeleton/loop/conventions follow [[squiral]]; the small-offscreen-field + upscale idiom mirrors [[metaballs]] (and [[strange]] / marbling).

## Config
`delay` (Frame rate, µs, 16000), `maxIter` (Iterations, escape cap, 150), `zoom` (0.3–4, 1), `morphSpeed` (orbit speed, 1), `ncolors` (Colors, palette size, 200), `cycle` (Color cycling, on).
- **`live: true`** — `delay`, `maxIter`, `zoom`, `morphSpeed`, `cycle`: read every step, apply instantly (none of them resize a buffer).
- **`live: false`** — `ncolors`: sizes the palette array, so a change re-runs `init()` via `reinit()` (which also reseeds the orbit and clears the canvas).
- `delay` uses `invert: true` (the xml's `convert="invert"` "Frame rate" slider), shown as the raw µs value with the `µs` unit escape.

## Deviations from the C
- **Escape-time instead of inverse iteration (the big one).** `julia.c` plots set points by *random inverse iteration* (repeated complex `sqrt` back-tracking down a binary tree of depth `--count`/`batchcount`), accumulating a point cloud. This port renders the **standard per-pixel escape-time field** instead — the universally recognizable Julia rendering, and a far better fit for a dense-field canvas blit. Consequently the xml's `count` slider (tree depth / number of plotted points) has **no analog and is dropped**; the xml's `cycles` slider (labelled **"Iterations"**, originally the erase-trail buffer count) is repurposed to the escape-time **max iteration count**, which matches its label.
- **Reduced internal resolution (mandatory retina cap).** The field is computed at logical resolution **capped to `MAX_FIELD = 720` px on the long side** (independent of `devicePixelRatio`), then upscaled by `drawImage`. Computing per-pixel escape-time at full device resolution on a retina/4K display would be seconds per frame. The bilinear upscale also softens the bands pleasantly. To restore full crispness, raise `MAX_FIELD` / set the grid to `canvas.width/height` and drop the upscale.
- **Orbit tuned to stay interesting.** The C's raw `incr()` orbit reaches `|c| ~ 2.4`, spending most of its time where the Julia set is a thin escaping "dust". The orbit is scaled (`ORBIT_AMP = 0.62`) and clamped (`ORBIT_MAX = 1.05`) so `c` stays near the Mandelbrot boundary where sets look richest. Measured over 500 frames `|c|` stayed in `[0.65, 1.05]` and the in-set fraction in `[0%, 7.7%]` — never an all-bounded (solid) or drifted-away frame. The C author's own comment notes the sinusoidal variation "might not be as interesting as it could," so this is a deliberate, documented improvement.
- **Colour.** The C cycles a single foreground colour through its palette each frame and plots all points in it; escape-time naturally wants per-escape-count banding, so this uses a smooth-iteration rainbow with an optional slow global hue rotation (`Color cycling`) to echo the C's per-frame colour change. Vivid `hsl` rainbow per the project's palette preference.
- **Control dot kept.** The C's small ring at the `c`-parameter (the xml description's "moving dot") **is preserved** — drawn at the `z == c` screen location, the same mapping the C uses. No XOR / feedback / stipple tricks were needed (the C's `GXxor`-free erase logic and `pointBuffer` redraw cycle are obsolete here because the whole field is recomputed each frame).
- **Default delay** set to 16000 µs (~one display frame) rather than the stock 10000, so it steps about once per refresh; calmer per the brief.

## Correctness self-review
- **Termination / no infinite loop.** The escape loop is bounded by both a bailout (`zr^2 + zi^2 > 4`) and `maxIter`, so every pixel halts; values stay finite (a pixel that would diverge bails the instant it crosses radius 2). Verified by a headless sim: 0 NaNs over 500 frames.
- **No blank / solid drift.** The clamped quasi-periodic orbit keeps `c` near the boundary (incommensurate sine periods, never a fixed point), so the set keeps moving and never settles into an all-escaped or all-bounded frame (in-set fraction measured 0–7.7%). The first frame is already a recognizable set for any random seed because every clamped `c` is in the interesting region.
- **No out-of-range / undefined reads.** The colour index is `floor(smoothN * idxScale + shift) % ncolors` with a `+ncolors` wrap for any negative result, and `smoothN` is clamped `>= 0` (it can go slightly negative for pixels that escape on iteration 0). Headless sim: 0 bad indices, 0 `undefined` palette reads over 500 frames.
- **Pause/resume & reinit.** Standard `rafId === 0` pause sentinel with `lastTime = 0` on resume (no catch-up burst); `reinit()` rebuilds the palette/grid, reseeds the orbit phase, and clears the canvas for a clean fresh scene on non-live config changes. The rAF lag-accumulator caps catch-up at `MAX_CATCHUP_STEPS`, so a slow machine (each frame is a full field recompute) or a backgrounded tab can't burst.

**Spot-check in the browser:** confirm the set morphs smoothly from frame one and the white control ring tracks the changing shape; drag **Iterations** (sharper/deeper detail), **Zoom**, and **Morph speed** (all live) and watch them apply instantly; toggle **Color cycling**; nudge **Colors** (reinit) and confirm a clean restart. Watch the **frame rate** on a retina display at high **Iterations** + low **delay** — the 720px field cap should keep it interactive; if it ever feels heavy, that cap (or `maxIter`) is the knob.
