# kaleidescope — port notes

Port of `kaleidescope.c` (Ron Tapia, 1997). The canonical **misspelling** ("kaleidescope", not "kaleidoscope") is preserved in the filename, `title`, and `info` to match the original hack.

Original: <https://www.jwz.org/xscreensaver/> · source: `xscreensaver-6.15/hacks/kaleidescope.c` (~513 lines).

## Algorithm
There are `nsegments` independent line segments (default 7), stored in a "natural" coordinate system centred on the origin. Each step every segment **propagates**: its midpoint orbits the screen centre by `global_rotation`, and the segment spins about its own (pre-orbit) midpoint by `local_rotation` (both angles are in units of `2*pi/10000` radians, so the defaults −59 / 1 are small per-step rotations). When a segment is drawn it is replicated across an **N-fold rotational symmetry group**: `symmetry` copies, each rotated by an additional `2*pi/symmetry` about the centre (the C's `NEWX/NEWY` rotation macros, applied iteratively), then translated by `(xoff, yoff) = (width/2, height/2)`. Each segment also keeps a **trail** of its last `ntrails` positions on a per-segment circular buffer (the C's ring of `Ksegment` nodes), so the figure leaves a fading kaleidoscopic ribbon. If a segment's two endpoints collapse to within `sqrt(100)=10` px of each other, it is re-seeded with fresh random endpoints (the C's `draw_ksegment` length check).

## Module shape
`start(canvas) -> { stop, pause, resume, reinit, config, params }` — see `[[squiral]]`. Trail/queue structure and per-step paced loop follow `[[spiral]]`; the Path2D-per-bucket stroke batching follows `[[braid]]`.

## Rendering — redraw the queue, bucketed by trail age (no X11 GC / XOR)
The C uses two X GCs: it draws the newest trail node with `draw_gc` and erases the **oldest** node (the `next` node in the ring) with `erase_gc` (background colour) each frame, overdrawing in place. Canvas has no equivalent persistent-overdraw GC scheme, and erasing anti-aliased strokes by painting black over them leaves residue and chews into overlapping trails. So instead the port **redraws the whole trail queue each frame** on a freshly-cleared black canvas. Segments are bucketed by **trail age** into one `Path2D` per age (newest = age 0), and each bucket is stroked once with an age-faded `hsl()` lightness (60% at the head fading to ~6% at the tail). That is `~ntrails` `stroke()` calls per frame (default 100), each carrying `nsegments * symmetry` little segments (default 7×11 = 77). Buckets are stroked oldest-first so the bright newest segments paint on top. No XOR (`GXxor`) or erase-GC is needed.

## Deviations from the C
- **No wall-bounce.** The spawning brief described the segments as "bouncing off bounds", but the actual `kaleidescope.c` has **no bounds-bounce** — the motion is purely the global-orbit + local-spin rotations above. The only radial wandering in the original comes from **integer roundoff** (the header even says so: *"the radial motion of the segments depends on roundoff error alone"*). This port reproduces that: endpoints/midpoints are stored as `short int` in the C, so the port truncates each assignment via `trunc16(v) = (v|0)<<16>>16` (round-toward-zero **and** the same 16-bit wrap on overflow). With normal window sizes the values stay well inside ±32767, so the wrap never fires in practice; it only guards against a runaway excursion, exactly as the C's `short` did. Dropping the truncation makes the figure rigidly rotate forever with no drift — visibly wrong — so it is load-bearing.
- **Draw/erase GC replaced by full-queue redraw** (see Rendering above). Visually equivalent constant-length fading ribbon, but cleaner (no anti-alias erase residue).
- **Trail seeded full from frame one.** The C's ring starts all-zeros and fills in over the first `ntrails` frames; until then those zero nodes draw a degenerate segment at the centre (a cluster of centre-dots). The port seeds every trail node with the segment's initial endpoints, so the kaleidoscope is **complete and symmetric on the very first frame** (the brief's correctness requirement).
- **Colour: cycling rainbow instead of fixed per-object colour.** The default `color_mode` is "nice", under which the C's `kcycle_color` is a no-op, so every trail node of an object shares **one** random RGB colour (a solid-colour ribbon) drawn from the `redmin/redrange/...` resources. The port drops those six colour-range resources and instead uses a vivid `hsl()` rainbow whose hue drifts slowly over time (`baseHue += 0.6/step`), per house style. Each segment also carries a `hue` offset field (currently the whole ribbon shares `baseHue`; the per-segment offset is wired but not mixed in, to keep the fade legible).
- **`narcs` / `spline.h` dropped.** The C scaffolds an extensible object system (`OBJECT` with `init/draw/propigate` vtables) and reserves an arc/ellipse object type, but `narcs` defaults to 0 and no arc object is ever implemented (`create_objects` only ever makes segments). The port implements just the segment object — identical output — and omits the unused vtable indirection and the `spline.h` include.
- **`spring_constant` dropped.** Read from resources by the C but never used anywhere in the file (dead). Not exposed.
- **Units / tuning.** `delay` is microseconds as in the xml, defaulted to 30000 (calmer than the stock 20000 by feel). The xml's `--symmetry` slider range (3..32) is used for the Symmetry param even though the C's internal default is 11; `--nsegments` 1..100, `--ntrails` 1..1000 match the xml. `local_rotation`/`global_rotation` are not in the xml's slider set but are real `-X` options, so they are exposed as live "Spin"/"Orbit" sliders (a fun live control; ranges chosen around the defaults). `fps`/keypress handling is dropped — the host owns the meter and keys.
- **devicePixelRatio.** Backing store sized in device px; line width is `round(dpr)` (→ 3 px above 2560 px, matching the C's Retina branch in `kaleidescope_reshape`). Endpoint magnitudes scale with `xoff/yoff` (= half the device-px canvas), so the figure fills the screen at any DPI.

## Correctness self-review
- **Closure / reset.** The only per-segment reset is the collapse check (`dx*dx + dy*dy < 100`), ported verbatim and evaluated once per step against the live endpoints; on reset the **whole trail is refilled** with the new endpoints, so there is never a half-reset frame mixing old and new geometry. The global-orbit motion means a segment's length is roughly preserved (a rotation is length-preserving up to roundoff), so collapse-and-respawn happens occasionally via drift rather than constantly — verified by reasoning, and the figure keeps moving (the rotation guarantees state changes every step; no state-machine branch leaves a segment frozen).
- **No freeze / no over-draw.** There is no termination condition to mis-fire: every frame propagates all segments and fully redraws from a cleared canvas, so a stuck closure test can't cause endless additive over-draw (the squiral/figure-port failure mode). The rAF lag-accumulator is the shared one (catch-up capped at 8 steps), so a long pause can't burst.
- **Symmetry centring.** The `NEWX/NEWY` rotation is about the origin and `(xoff,yoff)` is added **after** rotating, so all `symmetry` copies share the exact screen centre — the figure is centred and looks symmetric. The per-copy rotation is built as a running product of the single-step rotation (matching the C's iterated macro application), so copy `k` is rotated by `(k+1)*theta`; a full rotational set is invariant to that one-step starting offset, so the look is identical.
- **Buffers fixed-length.** Trail buffers are `Float64Array(ntrails*4)` allocated once in `init()`; `head` wraps with an explicit `if (head >= ntr) head = 0`; the backwards read in `draw()` wraps with Euclidean modulo `((idx % ntr) + ntr) % ntr`, so a fresh (head=0) buffer reads its newest entry correctly.
- **pause/resume + reinit.** `pause()`/`resume()` are the standard pair (`rafId===0` sentinel, `lastTime=0` on resume to avoid a catch-up burst). `reinit()` calls `init()`, which re-clears to black and re-seeds every segment + trail — a clean fresh screen.

## Spot-check in the browser
- First frame should already show a complete, centred, N-fold symmetric figure (not a dot cluster at the centre).
- The figure should slowly **drift/wander** (radial creep from the `short` roundoff), not just rigidly spin — if it looks perfectly rigid, the `trunc16` truncation regressed.
- Bumping **Symmetry** (reinit) should change the fold count and stay centred; **Spin/Orbit** sliders are live and should retarget the motion instantly without a jump.
