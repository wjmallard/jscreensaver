# anemotaxis — port notes

Port of `anemotaxis.c` by Eugene Balkovski (2004) — an "optimal search" simulation: odor **sources** on the left emit particles that drift right while random-walking in y (turbulent wind), and **searchers** enter from the right edge and crawl left to find a source, fanning out in expanding zig-zag "cones" until they sense a particle, then heading straight up the plume. Models how moths track pheromone plumes (odor-modulated anemotaxis).

Original: <https://www.jwz.org/xscreensaver/> · source: `xscreensaver-6.15/hacks/anemotaxis.c` (~759 lines).

## Algorithm
- **Lattice**: x in [0, `distance`], y in [0, 2·`distance`], mapped to device px by `X()`/`Y()` (the C's macros, `ax = W/distance`, `ay = H/(2·distance)`). `distance` is the "size of the lattice" (default 40).
- **Sources** sit near the left. Each holds a per-cell array `yvV/yvY` (velocity in {-1,0,1}, `2` = no particle; and the particle's relative y). `evolveSource` drifts every particle one cell outward (random-walking y by ±1) and probabilistically emits a new particle at cell 0 (rate `1/inv_rate`). A source whose emission is silenced (`inv_rate = 0`) is reaped once its last particle drifts away.
- **Searchers** carry a position, a cone `vertex`, a `state` (`UP_LEFT`/`UP_RIGHT`/`LEFT`/`RIGHT`/`DONE`), and a `hist` trajectory. `getV` tells a searcher whether a particle is at its exact cell and, if so, which way the wind blew it (`vel`). `moveSearcher`: if it senses a particle it steps one cell left and shifts y by `-vel` (climbing the plume), re-anchoring the cone; otherwise it walks the expanding triangular cone (up-left, sweep right to the diagonal, up-right, sweep left to the diagonal, …). Landing exactly on a source ends the search with a **white flash** (and silences the source); running off the left edge also ends it. A `DONE` searcher is reaped and respawned at the right edge.
- **Rendering** is a **full repaint each frame** (the C clears its back buffer every draw): source blobs (size grows with emission rate), drifting particles as small jittered squares, and each searcher's whole trajectory as one polyline (head → history, newest first). No persistent canvas / ring buffer — trails live in the history list. Contrast `grav`/`whirlwindwarp`, which keep a persistent canvas and erase-old/draw-new. See [[squiral]] for the shared skeleton, [[grav]] / [[whirlwindwarp]] for the particle-trail idioms.

## Deviations from the C
- **Searcher respawn rate (the one behavioral tuning).** The C respawns into a free slot with probability `1/(max_dist·max_searcher)`, which makes the *total* spawn rate ~independent of the Searchers slider — equilibrium settles at ~5 searchers no matter what you ask for, so the field looks nearly empty and the slider does almost nothing (verified in the harness: the stock formula crashed from a seeded 25 down to ~2–5 within ~8 s, momentarily hitting 0). We use `1/(maxDist·4)` so the slider genuinely scales the population and the fans stay lively (now holds ~13–25 active at the defaults). Everything else about spawning/dying is faithful.
- **Off-edge retirement hoisted out.** In the C the "ran off the left edge → `DONE`" test lives *inside* the per-source loop, so it never fires when no source happens to be active, letting a searcher wander off-screen indefinitely and grow its history without bound. We test `rx < 0 → DONE` unconditionally (same priority as the C when ≥1 source is active), so a searcher that leaves the field is always retired and history stays bounded.
- **Initial seeding.** The C boots with a single source and no searchers and fills in over ~20 s. We seed up to 5 pre-evolved plumes plus one searcher per slot, each advanced a random distance into the lattice (a guarded pure-cone walk), so frame 1 already shows fans spread between the right edge and the sources. Sources still accumulate toward `sources` over time as in the C; searchers come and go.
- **Color.** The C uses an X random colormap; we use a vivid HSL rainbow palette of `ncolors` (the stock `--colors` option, default 20; not shown in the original xml UI but exposed here like `grav`/`squiral`).
- **Particles drawn as `fillRect` squares** (not `XFillArc` circles) for cheap sparse drawing; the larger, fewer source blobs stay circular. Marker/particle size is `4·dpr` device px (the C's 4 px with its `>2560` retina bump folded into `dpr`).
- **`searchers = 0` mode not ported.** The C has a special mode (sources drift and self-destruct, no searchers); the xml slider's minimum is 1, so we always run with ≥1 searcher and omit that branch.
- **Encoding**: the only DOM-bound non-ASCII is the Frame-rate unit, written as the escape `' µs'`; literal Unicode appears only in comments (an em dash and a µ).

## Correctness self-review (won't freeze / over-draw)
- **Termination is guaranteed.** A searcher's x strictly decreases on every `UP_LEFT`/`UP_RIGHT`/sense move; the `LEFT`/`RIGHT` sweeps close on **integer-lattice** equalities (`vtx - rx === vty - ry`, etc.) which always fire because the sweep widens by exactly one each cycle — traced by hand and confirmed. So x reaches `< 0` in bounded time and the searcher is retired and reborn with all fields re-seeded (position, vertex, direction, distance via the lattice, color, empty history). No searcher can freeze.
- **Re-seed completeness**: `newSearcher` sets `rx/ry/vtx/vty/state/c/vel/rs/color/hist`; the `DONE → null → maybe newSearcher` path in `step()` mirrors the C's ordering (reap, respawn, found/off-edge test, sense, move), and a `DONE` searcher's `moveSearcher` is a no-op (default case), so its white flash shows for one frame before reaping.
- **No unguarded divides / no float-equality closures.** Screen mapping uses `Math.trunc` (matching the C's `(int)` cast, important since `rx` can be -1); `dx`/`dy` are floored with a `|| 1` floor; the cone closures compare integers. `getV` guards its index against `[0, n)`.
- **Headless harness** (4000 frames at the defaults, plus min/max edge configs): zero non-finite or degenerate (`r ≤ 0`) draw coordinates; max drawn coordinate stayed on-screen (≈2547 of 2560 dev px); active-searcher count stayed lively and never stuck; pause yields no pending frame, resume renders on its second tick (banks `lastTime` first, like the sibling hacks), reinit clears + re-seeds immediately; `distance=250 / sources=100 / searchers=100` seeds+reinits in ~7 ms with the seed-advance guard preventing any hang.

## Config
Units/defaults mirror `hacks/config/anemotaxis.xml`: `delay` (µs/step, 50000, `invert` Frame-rate slider), `distance` (10–250, 40), `sources` (1–100, 25), `searchers` (1–100, 25), plus `ncolors` (palette size, 20, from the C's `--colors` default). `delay` is `live`; the rest size the lattice/arrays/palette so changing them re-runs `init()` via `reinit()`.
