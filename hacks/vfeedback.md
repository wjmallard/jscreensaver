# vfeedback — port notes

Port of `vfeedback.c` by Jamie Zawinski (2018-2025) — "Simulates video feedback: pointing a video camera at an NTSC television." A camcorder aimed at the monitor it is plugged into re-grabs the screen it just drew — slightly rotated, zoomed and panned — and feeds it back ~30x a second, folding the image into endless tunnels and spirals. See [[kumppa]] for the scratch-canvas self-feedback idiom this shares and [[squiral]] for the module skeleton.

Original: <https://www.jwz.org/xscreensaver/> · source: `xscreensaver-6.15/hacks/vfeedback.c` (~591 lines, much of it X11 grab/event plumbing and the unported NTSC `analogtv` pipeline).

## Algorithm
The C keeps a normalised **camera rectangle** `rect = {x, y, w, h, th}` describing the sub-region of the previous frame the camcorder is aimed at: `x,y` pan (fraction of frame), `w,h` zoom (1 = whole frame), `th` rotation (radians).

- **State machine** (`POWERUP -> IDLE -> MOVE`): each `MOVE` eases `rect` from `orect` (the pose at the start of the move) toward `orect + {dx, dy, dth}` and `orect.w * (1 + ds)`, with the ease parameter `value` advancing `0.03 * speed` per frame through an ease-in-out-sine. When `value > 1` the next pose is chosen: `IDLE -> MOVE` rolls fresh random pan / zoom / rotate deltas (each gated by a `random()%N`, so most moves change only one axis); `MOVE -> IDLE` pauses briefly (`value = 0.3`). Rarely (`random()%2000`) it re-twiddles the TV knobs, and `random()%20000` re-rolls the whole camera framing.
- **`grab_rectangle`** is the feedback core: it `XGetImage`s the whole window and, for every output pixel, samples the input at `ix,iy` computed by recentring on the frame middle, scaling by `rect.w/h`, rotating by `rect.th`, and offsetting by `rect.x/y`. Out-of-range samples read `black`. That resampled image is handed to `analogtv`, which re-renders it as a noisy NTSC frame (colour / tint / brightness / contrast knobs), and the result becomes the next frame the camera grabs.
- A moving **specular reflection** (`XFillArc`, an eased disc) is injected near the centre every so often (`random()%300`) and fades in/out over its own `svalue` — the bright glare the tunnels chase, standing in for stray room light. The `analogtv` `tint_control` also wanders, slowly cycling the colour.

## Shared skeleton (inherited)
Standalone ES module exporting `title` + `info` + `start(canvas) -> { stop, pause, resume, reinit, config, params }`; rAF **lag-accumulator** loop at a fixed timestep (`config.delay` microseconds, default ~33 ms = the C's 29.97 fps budget) replacing the C's per-frame `timedelta` sleep; `devicePixelRatio` folded into `S` and the backing store sized in device px; descriptive names; one-item-per-line params.

## Deviations from the C
- **Canvas self-feedback replaces the X11 grab + resample (the load-bearing one).** There is no canvas equivalent of `XGetImage` + a hand-written per-pixel affine resample. Instead each frame copies the current canvas into a **scratch canvas**, clears the main canvas to black, then redraws the scratch back through the inverse camera transform — `ctx.translate(cx + rect.x*W, cy + rect.y*H) / rotate(rect.th) / scale(1/w, 1/h) / translate(-cx,-cy) + drawImage(scratch)`. The scratch copy is required because `drawImage` cannot safely read and write the same canvas through a transform (same reason as kumppa). drawImage's bilinear sampling *is* the smear. The scale is `1/w` (not `w`) because the C samples the *output* coordinate through `rect.w` to find the *input* pixel; doing that as a forward canvas transform on the output inverts it, so a `rect.w > 1` (camera zoomed out) correctly shrinks the image toward the centre (tunnel inward), matching the C. Out-of-frame pixels come back transparent over the black fill, exactly the C's `black` border.
- **`analogtv` NTSC pipeline is not reproduced.** The full C re-renders every frame through a simulated NTSC signal (luminance/chroma separation, scanlines, dot crawl, ghosting). Reproducing that faithfully is a hack of its own. The *visible* contributions that shape the feedback are emulated directly: (1) a slow **hue drift** applied to the fed-back image each frame via `ctx.filter = hue-rotate(...)` (the `tint_control` wander — "Tint Knob"); (2) a faint **static** overlay (a small regenerated noise tile stamped with `screen` blend at low alpha — the `noise` resource); (3) a **feedback gain** `< 1` (a `globalAlpha` multiply on the fed-back image — the analogtv contrast/level the C randomises, here surfaced as a "Feedback" depth slider). Scanlines / phosphor dots / chroma artefacts are dropped. `ctx.filter` is supported in every current browser; if one lacked it the tunnel would simply not cycle colour (guarded with `if (ctx.filter !== undefined)`, no crash).
- **Mouse/keyboard interaction dropped.** The C lets you pan/zoom/rotate the camera and tweak TV knobs live by mouse + keys. The host owns input in jscreensaver, so the camera just auto-drifts (the C's non-`button_down_p` path); the knobs are exposed as config-box sliders instead.
- **Specular glare look.** Drawn as a soft radial gradient (warm white -> the C's `#CCCC44` foreground -> transparent) rather than a flat filled arc, which reads more like a real reflection through the bloom of the feedback.
- **Power-on seed.** The C starts black and waits for a specular to spawn; an all-black canvas would feed back as black until then. We seed a bright central blob in `init()` so the *first* frame already has something to fold (the "camera just powered on" flash) — no degenerate empty start.
- **Encoding.** The Frame-rate slider unit is written `µs` and the Tint unit `°/step` (no literal non-ASCII in a rendered string); em-dashes / the `↔` arrow appear only in comments.
- **Calmer default.** `delay` defaults to 33367 microseconds (~29.97 fps, the C's native rate); the lag accumulator paces it identically at any refresh rate. `MAX_CATCHUP_STEPS` is 4 (vs 8 elsewhere) because each step does a full-canvas `drawImage` + filter — capping catch-up lower keeps a refocused tab from doing expensive bursts.

## Correctness self-review
The standing risk for a self-feedback hack is the loop running away to **all-black** (content collapses inward to nothing) or **all-white / flat** (content saturates). Traced and modelled (see `scratchpad/stability.mjs`):
- **No white-out — the gain is a hard bound.** The fed-back image is drawn with `globalAlpha = gain`, clamped in code to `[0.5, 0.985]` and by the slider to `[0.85, 0.985]`. Average brightness obeys the fixed point `B* = inject / (1 - gain*retained)`, where `retained < 1` is the fraction of the rotated frame still landing on-canvas. The denominator `1 - gain*retained` is strictly positive because `gain <= 0.985 < 1` (and a real rotation of `th >= 0.2` rad always spills some of the frame off the edge, so `retained < 1` too) — so `B*` is finite for every slider position. The numerical sweep confirms steady brightness stays in a healthy mid-range (~7-170/255 at the default `gain = 0.94`) and only diverges at the impossible `gain = retained = 1`.
- **No black collapse.** With any energy injected per frame (the specular fires ~1/300 frames and the noise overlay only *brightens*, via `screen`), the steady `B* > 0`. The `init()` seed blob means frame 1 is already lit, so the recursion has fuel from the start rather than waiting for the first random specular.
- **No pinned hot spots.** Every camera pose has `rect.th >= 0.2` rad and the `MOVE` deltas keep it turning, so no pixel ever maps to itself across frames — a bright specular gets swept into the spiral and fades, it can't sit and bake a saturated dot.
- **State machine re-seeds what the next state reads.** Each `value > 1` transition resets `value` and the `d*` deltas before choosing the next state; `IDLE -> MOVE` rolls new deltas, `MOVE -> IDLE` sets `value = 0.3` (the C's brief pause). `POWERUP` falls straight into `IDLE` on the first frame so the camera is live immediately. The specular path resets `svalue` and `spec.s` together (set both, or clear both), so it can never be "active with no fade" or "fading with no disc".
- **Transform hygiene.** `feedback()` is wrapped in `save()/restore()`, and every other draw (`drawSpecular`, `drawNoise`, the seed, the black fills) calls `setTransform(1,0,0,1,0,0)` first, so the camera transform can never leak into a flat fill or the overlay draws. `globalAlpha` / `globalCompositeOperation` / `filter` are always restored to their defaults before the next primitive.
- **Pause/resume / reinit.** `pause()` cancels rAF (`rafId = 0` sentinel); `resume()` zeroes `lastTime` before re-arming so no catch-up burst fires — the tunnel resumes from the frozen framebuffer. `reinit()` and `resize()` reset the transform, clear to black, and re-run `init()` (rebuilding the scratch + noise canvases, re-rolling the camera, zeroing hue/value/state, re-seeding the flash) — a clean fresh screen with no stale transform or camera pose.

## Config
Mirrors `hacks/config/vfeedback.xml` + `vfeedback_defaults[]`: `delay` (microseconds/step, 33367 ~= 29.97 fps, `invert:true` Frame-rate slider showing raw microseconds), `speed` (camera drift rate, 0.1-3, default 1.0 = `--speed`, `live`), `tint` (hue drift degrees/step, the analogtv tint wander = xml "Tint Knob", `live`), `gain` (feedback depth 0.85-0.985, the analogtv contrast/level, `live`), `noise` (static strength 0-0.2 = `--noise` / "Noise", `live`). All knobs are `live: true` (they read `config[key]` every frame and apply instantly); `reinit` re-rolls the camera geometry and re-seeds. The xml's brightness/contrast/colour knobs collapse into `tint` + `gain` here since the full NTSC colour pipeline is not reproduced.

**Local dev:** ES-module imports mean `file://` double-click won't load it (CORS on the `null` origin). Serve it — `python3 -m http.server`, then <http://localhost:8000/#vfeedback>. GitHub Pages serves over http, so production is unaffected.
