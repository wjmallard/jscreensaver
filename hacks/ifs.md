# ifs — port notes

Port of `ifs.c` by Chris Le Sueur & Robby Griffin (2005-2006), after Massimino Pascal's original xscreensaver hack; multi-colour mode by Jack Grahl (2007). Clouds of Iterated Function Systems spin and collide: a few affine "lenses" define the IFS, the chaos game folds a point through them plotting one dot per iteration, and every frame the lenses morph so the fractal writhes.

Original: <https://www.jwz.org/xscreensaver/> · source: `xscreensaver-6.15/hacks/ifs.c` (~559 lines). See [[squiral]] for the shared skeleton, [[thornbird]] / [[hopalong]] for the accumulate-into-a-blit-buffer technique this follows.

## Algorithm
- **Lenses (affine maps).** Each lens has a rotation `r`, scale `s` and translation `tx, ty`. `lensmatrix()` precomputes a 2x2 matrix + offset vector `(ua,ub,uc,ud,utx,uty)` in fixed point: the matrix carries an extra factor of 2^10 and coordinates an extra 2^8, so a step is `(ua*x + ub*y + utx) >> 10` (and likewise for y). `ua = 1024·s·cos r`, `ub = -1024·s·sin r`, `uc = -ub`, `ud = ua`; the offsets centre and scale the figure to the canvas.
- **Chaos game (`iterate`).** Start at the canvas centre (in 256ths of a pixel), repeatedly pick a random lens and apply it; drop the first 10 iterations (burn-in onto the attractor), then plot every later point. Points per pass = functions^(detail-1); "Detail" is exponential.
- **Multi mode (default).** One pass per lens. Pass `i` plots in its own palette colour and applies one extra fixed transform `lens[i]` before plotting, fanning the cloud into per-lens sub-clouds. The base colour index advances each frame so the whole thing rainbow-cycles.
- **Morph (`mutate`).** Every frame, each lens eases toward fresh random targets: rotation and scale interpolate sinusoidally (a counter `+= 0.01` per frame, re-rolling a new target when it wraps past 1 — about a 100-frame cycle); translation drifts on a wandering velocity `txa/tya` that is randomly nudged and pulled back when `|tx|,|ty|` exceed 6 or the velocity exceeds 0.05. Then `lensmatrix()` recomputes the fixed-point coefficients.
- **Dedupe + plot (`sp`).** Coordinates arrive in 256ths of a pixel; `>>8` gives the pixel. A per-frame bit board (`getdot/setdot`) ensures each pixel is painted at most once per frame, and out-of-range points are simply dropped (which doubles as the divergence guard). Points are drawn as a `pscale`-sized dot (1px, or 3px on >2560px retina displays, matching the C).

## Rendering
Tens of thousands of points per frame (3^8 ≈ 6.5k × functions passes ≈ 20k+ at defaults), so this uses the **blit path**: a persistent `Uint32Array` view over an `ImageData`, plot/erase pixels, `putImageData` once per frame — not per-point `fillRect`. Palette is a vivid `hsl(h,100%,55%)` rainbow (`config.ncolors` entries, floored to at least `functions` like the C).

## Deviations from the C
- **Full-buffer clear each frame instead of dirty-bbox erase.** The C tracks the bounding box of the points drawn and erases only that rectangle on the next frame (plus double-buffering / `XCopyArea`). Here the whole `Uint32` buffer is `fill(BLACK)` each step before redrawing — for a typed-array blit that is just as cheap and removes all the bbox/`XCopyArea` bookkeeping. Visually identical (the figure is fully redrawn every frame in both).
- **Fixed-point math kept in float64, shift replaced by `Math.floor(v/1024)`.** The C does `(ua*x + ub*y + utx) >> 10` in 32-bit `int`. On a 4K canvas the pre-shift intermediate reaches ~3.0e9, which **overflows int32** (2.15e9) — a JS `>>10` would coerce to int32 first and produce garbage. Keeping the products as float64 and using `Math.floor(.../1024)` reproduces the C's arithmetic right-shift (floor division, correct for both signs) without the overflow. Verified numerically: at 4K the float64 path gives 2.91e6 where `(inter|0)>>10` gives -1.28e6.
- **Point budget capped.** Points-per-pass is clamped to 4,000,000 so a high "Detail" on a slow machine can't lock the tab (the C trusts the user; "Detail" is exponential — 14 means functions^13 points). At the default detail 9 this cap is never reached.
- **`mode`, `recurse`, `multi` not surfaced.** The stock UI (ifs.xml) exposes only delay / functions / detail / colors and the translate/scale/rotate toggles. We follow the C defaults `recurse=False` (so we port the `iterate` chaos-game path, not the exhaustive `recurse` tree) and `multi=True` (the per-lens coloured loop). `mode` is unused in the C.
- **Encoding:** the only DOM-bound non-ASCII is the micro sign in the frame-rate unit, written as `'µs'`. Literal Unicode (em dashes, µ) appears only in comments.

## Config
Units/defaults/ranges mirror `hacks/config/ifs.xml`: `delay` (µs/frame, 20000, `invert` "Frame rate" slider), `functions` (2–6, 3), `detail` (4–14, 9, exponential), `colors` (2–255, 200), and the `translate` / `scale` / `rotate` morph toggles (all on). The translate/scale/rotate toggles are **live** — the morph reads them each frame, so disabling one freezes that axis instantly (matching the original's intent, where they gate the mutate branches). `functions` / `detail` / `colors` are **not live** (they resize the lens set, point budget and palette), so changing them re-seeds via `reinit()` with a fresh figure. Default delay matches stock (20000 µs).

## Correctness self-review
Traced by hand and exercised in a headless harness (300 frames, ~5.9M points, full mutate loop):
- **No divergence / NaN.** 0 NaN over 5.9M points; max |coord| stayed ~3.4e5 (in 256ths, ~1300px past the edge) — the morph's translation pull-back and scale bounds keep the attractor bounded, and `sp()` drops anything off-canvas, so a runaway lens can't paint garbage or stall.
- **Fills the frame.** 99.8% of plotted points landed on-canvas at defaults — the offset/scale centring fills the canvas rather than collapsing to a dot or drifting off-screen, and the very first frame already looks right (centre seed + burn-in).
- **Morph never stalls.** The rotation/scale counters reset (`rc/sc = 0`, pull a new target) when they pass 1, so they cycle forever rather than sticking at a target (the "dead-figure" failure mode the brief warns about); the translate velocity is pulled back before it can run away. The harness confirmed lens parameters keep changing across frames.
- **Per-frame state re-seeded.** Each `step()` resets the chaos-game point to the centre, clears the bit board and the pixel buffer, and advances the colour — nothing leaks across frames.
- **Pause/resume/reinit.** Loop is the standard lag-accumulator (`resume` resets `lastTime` so no catch-up burst); `reinit()` re-runs `init()` for a clean fresh figure.
